# Week 4, Day 1 — Meet Copilot Agent Mode
*v1.0.0*

**Goal for today:** switch Copilot on inside VS Code, point it at brand-lens, and take a read-only tour. Three new rules — review every diff, never auto-approve a command, ask before committing unclear code — replace Week 2's two rules. By end of day Copilot has explained your repo to you and you haven't kept a single edit yet.

**Time budget:** ~75 min hands-on, ~15 min journal, ~30 min slack.

---

## About the tool — what changes today

You met Copilot in a browser tab on W02D1. That was a chat: paste code, read explanation, type code yourself. Today Copilot moves into VS Code, and gets **agent mode**. It's the same Copilot — but now it can read every file in your repo, edit them, and run commands in a terminal. The chat is now a colleague who has hands.

The Copilot chat panel in VS Code has a **mode picker** at the bottom of the prompt box. Two modes matter in this course:

- **Ask** — read-only. Copilot can look at your files and answer questions, and it can show code in its reply, but it can't change anything on disk.
- **Agent** — hands. Copilot can edit files, create files, and run terminal commands (after asking you) to finish a task.

(You may also see **Plan** or other modes in the picker. Ignore them for now.)

That power needs new rules. Week 2 had two:

1. Ask Copilot to explain, not to write.
2. Run everything yourself.

Week 4 has three:

**Rule 1: Review every diff before keeping it.** In agent mode, Copilot's edits show up in the file as a diff — added lines highlighted green, removed lines red — with **Keep** and **Undo** buttons. Read every line before you press Keep. If you keep a diff you didn't read, you don't own the code — and you can't debug it later.

One thing to know: the edits are already *in the file* the moment Copilot makes them — Keep and Undo decide whether they stay. So if you run your script before deciding, you're running Copilot's version. Decide first.

**Rule 2: Never auto-approve a command you can't explain.** Agent mode asks before running terminal commands — a box shows the command with an **Allow** button. The temptation to hit Allow is real. Don't. If you don't know what `rm -rf node_modules` does, press **Skip**, ask why it wants to run that, then decide. The Allow button has a dropdown with "always allow" options — never use them in this course.

**Rule 3: If a line is unclear, ask before committing.** When Copilot edits a line you don't fully understand, ask Copilot to explain *that line* before you commit. Don't commit code you can't read.

These rules tighten as you get more access, not loosen.

## 1. Warm-up (~5 min)

Activate venv. From inside `~/dev/brand-lens`:

```
source .venv/bin/activate
python3 runner.py --limit 1
```

Confirm Week 3's pipeline still works. You'll need this baseline tomorrow.

## 2. Switch Copilot on in VS Code (~15 min)

On W01D1 you ticked **Chat: Disable AI Features**. Undo that now:

1. Open VS Code. Press **Cmd-,** for Settings, search `disable ai features`, and **untick** it.
2. A Copilot icon appears in the status bar at the bottom of the window. Click it and choose **Sign in** (or "Set up Copilot"). It opens a browser; sign in with the same GitHub account you've been using at github.com/copilot. Come back to VS Code.

Now one setting you'll turn *off* on purpose. Copilot has two features in the editor: the **chat** (you ask, it answers or edits, you review) and **code completions** — grey "ghost text" that appears as you type, which a single Tab press accepts. Ghost text skips every rule above: there's no diff to read, no moment to say no. Switch it off:

1. Press **Cmd-Shift-P**, type `Open User Settings (JSON)`, hit Enter.
2. Inside the outer `{ }`, add this line (keep the commas valid — if there are other lines, put a comma at the end of the one before):

```json
"github.copilot.enable": { "*": false }
```

3. Save (Cmd-S).

Open any `.py` file and type a few characters of a new line. No grey text should appear. If it does, check the JSON for a typo.

**What just happened:** VS Code's settings are a JSON file — the same `{ "key": value }` shape as your `results.json`. The Settings screen is just a friendly editor for that file. You'll edit it directly again later.

## 3. First session — open the repo (~10 min)

In your terminal:

```
cd ~/dev/brand-lens
code .
```

The `.` means "this folder" — VS Code opens the whole project, not just one file. Now open the chat panel: **Ctrl-Cmd-I** (or the chat icon at the top of the window). Set the mode picker to **Ask**.

Copilot can now see every file in this folder. In Ask mode it can only read. Tomorrow and after, you'll use Agent mode — where it can edit and run things, but only by showing you what it's doing.

## 4. Read-only tour: ask it to summarize (~15 min)

You're going to use Copilot as a reader, not a writer, today. In **Ask** mode, type:

> Summarize the structure of this repo. What are the main files, and what does each one do? Don't make any edits.

Read the response carefully. Compare it against what you know is true:

- Are the file descriptions accurate?
- Did it claim a file does something it doesn't?
- Did it miss a file or invent one?

Notice the "used references" list Copilot shows above its answer — those are the files it actually opened. If it describes a file that isn't in that list, it's guessing.

This is the same calibration exercise as W02D1's first Copilot session — except now Copilot is reading the actual files, not what you pasted. Its accuracy will be different.

## 5. Ask about a specific function (~15 min)

Pick one function from `runner.py`, `fetch.py`, or `parse.py` — ideally the one you struggled to explain in W03D5 prep. Still in Ask mode:

> Walk through `process_url` (or whatever you picked) line by line. Treat me like someone four weeks into Python.

Read the explanation. For every line:

- Does the explanation match what you understand?
- Is there a line where Copilot's explanation makes more sense than yours?
- Is there a line where Copilot is confidently wrong?

## 6. Notice the temptation to skim a diff (~10 min)

Now switch the mode picker to **Agent** and ask for a small edit — and then *don't keep it*:

> Make a small improvement to `runner.py`. Keep it to a few lines.

Copilot edits the file. The changed lines light up green and red in the editor, with **Keep** / **Undo** controls in the editor and in the chat panel. Watch what you feel. Is there a pull to skim and press Keep? That pull is real. Notice it now, while there's no pressure.

Read every green line. If anything is unclear, ask in the chat:

> Explain the line you added that starts with `...` in plain language.

Then press **Undo** for today. The file goes back to exactly what it was. You can revisit the idea tomorrow.

## 7. Close the session, commit nothing (~5 min)

Start a fresh chat (the **+** at the top of the chat panel) so tomorrow starts clean. There should be nothing to commit — you didn't keep any edits. Run `git status` to confirm:

```
git status
```

Should say "nothing to commit, working tree clean." If it doesn't, an edit slipped through — run `git diff` to see it and `git restore <file>` to throw it away.
